# 酷狗概念版每日 VIP · Loon

在已登录酷狗概念版的设备上，通过 Loon 捕获 App 请求中的登录凭证，再每天查询领取记录并领取当天概念版 VIP。无需扫码登录、服务器或公开的第三方 API。仅支持单账号；切换酷狗账号后，打开 App 重新捕获。

> 实机 `appid=3114 / clientver=12491` 的月度查询和 **Web 领取**均已返回业务成功，领取配置已在手机保存。新安装仍需手动验收自己的账号后再开启定时。默认时间为每天 **06:00**。后台凭证更新已通过本地模拟测试，真实 Token 轮换仍需实机观察。

## 文件

| 文件 | 用途 |
| --- | --- |
| `kugou-concept-vip.plugin` | Loon 插件、动态 Cron 和 HTTPS 解密域名 |
| `capture.js` | 从酷狗请求的 Cookie、Authorization 或 URL 参数读取凭证，保存到 Loon 本地 |
| `claim.js` | 查询月度记录，确认未领后提交一次当天领取，并发出通知 |
| `diagnose.js` | 手动检查请求是否命中及必要字段是否出现，不显示凭证值 |
| `signature-check.js` | 本地核对 GET/POST 签名；对两个指定 VIP 接口保存验签成功的执行配置，日志只显示脱敏摘要 |

使用 Loon 3.5.1 (983) 或更新版本。插件采用[新版 Script 语法](https://nsloon.app/docs/Script/script_v2/)；脚本使用 [Loon Script API](https://nsloon.app/docs/Script/script_api/)。

## 安装和首次验收

1. 在 Loon 的插件页面添加 `https://raw.githubusercontent.com/changeCat/kugou-concept-vip-loon/main/kugou-concept-vip.plugin`，并启用插件。也可以使用[插件导入 Scheme](https://nsloon.app/docs/Scheme/)。插件会自动下载脚本，无需单独导入。
2. 在 Loon 安装并信任 HTTPS 解密证书，确认插件的 `*.kugou.com` 域名已经参与 MitM。无需把证书或账号凭证写入仓库。
3. 先退出普通酷狗和酷狗畅听版，普通的“启用凭证捕获”可以关闭。开启“临时签名诊断”，只打开**酷狗概念版**的 VIP 领取记录页面，看到“月度查询配置已保存”后关闭开关。这一步将配套登录态、设备字段、`uuid/srcappid` 和签名类型保存在手机本地。
4. 手动运行 **“仅查询 VIP 记录”**，确认使用 App 配置的查询成功。这一入口只发 GET，不领取，也不修改领取状态。
5. 若尚未保存领取配置，在**当天未领取、尚未打开 App 领取时**，运行 **“测试 Web 领取（当天一次）”**。先查记录，确认未领取后只提交一次 Web 签名的领取请求。已经领取时跳过；查询失败、记录不明确时不提交；领取失败或超时后，当天不重复提交。今天已领取可等下一天再测试，无需再次捕获相同的原生领取样本。
6. 看到“Web 领取请求成功，领取配置已保存”并核对 App 权益后，开启“启用自动领取”。默认每天设备本地时间 `06:00`（`0 6 * * *`）。**已有安装需在插件参数“领取时间”手动将旧值改成 `0 6 * * *`**，Loon 优先保留用户已保存的参数。以后可用手动入口或定时任务复用成功配置。关闭“启用凭证捕获”和“临时签名诊断”，保留“后台凭证更新”。若测试失败，提供该入口的脱敏日志，保持自动领取关闭。

已有经本地验签保存的领取配置时，也可直接用“手动核对并领取 VIP”验收；Web 测试入口会复用已有配置，不覆盖它。原生领取样本的学习方式保留在下方诊断说明中。

不需要每天重新捕获。普通捕获不会覆盖已保存的执行配置；后台凭证更新是独立功能，见下节。切换账号、重装 App 或设备身份变化时，需要重新学习该账号的查询配置并验收领取；后台更新只接收同一 App、账号和 `mid` 的新 Token。临时签名诊断重新学习不同身份时仍会清除上一会话的配置。

## 凭证过期与打开 App 更新

登录凭证可能失效，项目没有可靠的固定有效期信息，也不能仅凭 `51002` 等错误码判断一定是过期。插件不主动调用登录刷新接口：由 App 维持登录或重新登录，再接收它发出的新 Token。

- 保持插件、MitM 和 **“后台凭证更新”**开启。只打开概念版即可监听普通网关请求，无需特意进入 VIP 页面。必须实际出现携带 `appid=3114`、同账号、同 `mid` 和新 Token 的请求；只打开 App 但没有产生这些字段时，无法更新。App 提示登录时先重新登录。
- 发现新 Token 后，沿用已成功的 Web 查询配置发起一次只读验证。查询业务成功才同步更新查询及领取配置中的 Token，保留设备字段、签名规则和领取参数；不会在捕获时领取，也不会清除当天的防重复领取状态。
- Token 没变时不额外查询、不通知；新 Token 验证每分钟最多一次。验证失败保留原配置，可在“检查酷狗捕获状态”查看最近验证结果。成功通知为 **“登录凭证已更新”**，之后下次定时使用新凭证；需要当天立即执行时，可运行“手动核对并领取 VIP”。
- **后台监听仍会产生 Loon 运行记录。** 默认按概念版 App ID、带 Token 的请求过滤；不保证仅产生一条记录。关闭它可停止此类记录，但也会停止“打开 App 更新凭证”。[Loon 的条件和匹配规则](https://nsloon.app/docs/Script/script_v2/)不支持用脚本本地存储决定是否触发 HTTP 脚本，脚本内部去重不能消除运行记录。
- 切换账号、`mid` 改变或查询配置本身失效时不会混用旧设备配置，需要重新进入 VIP 记录页面学习。这属于重新配置；通常同设备同账号的 Token 更新无需这一步。实际 App 启动请求能否提供上述字段，仍需手机验证。

进入 App 会发起多条请求，因此可能出现多条“酷狗凭证捕获”运行记录。记录数不等于保存次数，也不等于领取次数。默认活动路径过滤从 Loon 规则层减少触发，不对具体记录数作保证；如果 App 多次请求活动接口，仍会产生多条记录。在 JavaScript 中去重、减少存储写入或提前 `$done()` 无法消除已经触发的运行记录。`debug` 默认即为 `false`，不能将其当作禁用运行历史的选项。

**只保留日常凭证更新：关闭“启用凭证捕获”和“临时签名诊断”，保留“后台凭证更新”。** 若要停止所有监听记录，再关闭“后台凭证更新”。这些开关不会删除本地配置或关闭手动/定时任务；关闭开关不会删除既有运行记录。

## 领取规则

- 每次运行先请求 `/youth/v1/activity/get_month_vip_record`。已确认今天领取过时跳过。
- 自动任务和“手动核对并领取 VIP”仅在月度记录能够明确判断“今天未领取”且已有配套领取配置时，对 `/youth/v1/recharge/receive_vip_listen_song` 发送一次 POST。每次更新 `clienttime`，若配置含 `receive_day` 则更新为设备本地当天，不传未来日期。
- “测试 Web 领取（当天一次）”允许在缺少领取配置时进行一次兼容性测试：沿用验签通过的 Web 查询会话，使用领取路径、`source_id=90139` 和当天 `receive_day`，发送空请求体的 POST。路径和参数参考 [KuGouMusicApi 的领取模块](https://github.com/MakcRe/KuGouMusicApi/blob/main/module/youth_day_vip.js)；该参考使用 Android 签名，**不能证明 Web 领取可用**。只有本次业务响应成功才将测试配置保存到 `kgcv.native.v1`，失败不会交给定时任务。定时任务不会自行生成测试配置。
- 发出领取请求前先保存“结果待确认”状态。网络超时、业务失败或脚本中断后，当天后续运行只复查远端记录，不重复提交。
- 月度记录字段不认识、查询失败、凭证不完整时停止并通知。领取成功后保存当天成功状态。
- Token 和设备字段只保存在 Loon 的 `$persistentStore` 中；通知仅显示账号尾号或结果。不要公开 Loon 的脚本存储、抓包记录或包含凭证的配置。

## 验收时可能遇到的问题

| 现象 | 检查方式 |
| --- | --- |
| 打开 App 后没有“凭证已保存”通知 | 运行“检查酷狗捕获状态”。若没有命中请求，确认 Loon 正在处理概念版的 HTTPS 请求、脚本与 MitM 已启用、证书已信任；若已命中但字段不全，请只提供诊断通知中的域名、App ID 与字段有无，不要发送 Token、Cookie 或完整 URL。 |
| 手动运行“检查酷狗捕获状态”也没有通知 | 查看 Loon 的脚本运行日志。若脚本未运行，检查插件是否已更新并启用、脚本开关是否打开；若有日志但没有通知，检查 Loon 的系统通知权限。 |
| “尚无完整凭证” | 手动打开概念版 App 并浏览个人或活动页面；目前必须从同一条请求或同一账号的已有记录得到 `mid`。 |
| “无法确认今天是否已领取” | 月度记录返回形状或错误码与脚本认识的格式不同。查看 Loon 运行状态；仅提供脱敏后的响应字段名和错误码来适配，勿贴 Token。 |
| 旧版记录查询返回 `51002` 或对照返回 `2006 / err signature` | 更新后不再运行该对照。开启临时签名诊断，重新进入记录页面保存验签通过的配套参数，再执行“仅查询 VIP 记录”。 |
| 查询成功但尚缺领取配置 | 当天尚未领取时，手动执行“测试 Web 领取（当天一次）”。成功后保存配置；月度查询成功本身不证明领取签名可用。 |
| POST 请求体不可用 / 字段未适配 | 提供“检查 App 签名”的脱敏日志；此时未保存领取配置，不能开启自动领取。 |
| “领取请求结果不明确” | 先到酷狗 App 查看权益。脚本为防止重复提交，不会在今天再次请求领取。 |
| App 配置查询仍被拒绝 | 提供脱敏错误码与日志，继续核对请求头或登录态；不要重复尝试领取。 |

捕获诊断中的“最近命中 App ID”属于最近一条请求；普通捕获和 App 已验签配置分开保存。仅有普通的 `3114` 凭证时，脚本会提示学习接口，不再借用 Android 配置。若普通捕获与已验签配置的账号不同，脚本停止，避免对错误账号领取。

通知关闭时，可在脚本日志查看领取结果；同时检查 Loon 内的脚本通知开关和系统通知权限。日志不输出完整响应、请求 URL、Token 或 Cookie。

## 可选：核对 App 原生签名

诊断使用 **App 自己发出、业务响应成功** 的请求作为样本核对签名。已经得到“原生领取成功但签名未匹配”的结果时，不必每天重复取相同样本；可先按上面的步骤测试 Web 领取。

1. 更新插件和远程脚本。保持“启用自动领取”关闭；已有凭证时，“启用凭证捕获”也可以关闭，本地签名核对是独立的响应规则。
2. 手动运行“清除签名诊断摘要”，然后开启“临时签名诊断”。
3. 查看领取记录以学习查询；需要学习原生领取时，在当天未领取的情况下于 App 内正常领取一次。
4. 关闭“临时签名诊断”，手动运行“检查 App 签名”，提供该日志即可。

诊断接收 `gateway.kugou.com/youth/` 下 `appid=3114` 的 GET/POST 样本，本身不发出网络请求、不重放请求、不改变响应。它用 KuGouMusicApi 公布的 Android Lite、Android 标准版、Web 三种公式本地计算。摘要存于 `kgcv.signature.v1`，不包含参数值。

**诊断的存储行为：** 仅对月度查询 GET 和当天领取 POST，在签名匹配、业务响应成功且字段通过白名单验证后，将执行所需的登录态、设备参数、签名类型、必要请求头及已支持的请求体保存到 **`kgcv.native.v1`**。手动 Web 测试业务成功后也会将领取配置存入同一位置。不保存完整 URL、Cookie、旧签名或响应正文；通知和日志不显示凭证值。清除诊断摘要不会清除执行配置。已有月度配置可以继续使用，无需为了本次升级重新捕获。

- **匹配公开算法**：只证明对应样本可复算，需进一步验证脚本的新请求。其他活动接口匹配不会自动成为领取配置。
- **未匹配**：目前检查 URL 参数和可用的请求体；仍可能有其他字段参与签名，不能仅凭不匹配断言密钥不同。
- **暂无样本**：App 可能未发出匹配路径的 GET 请求，或被其他响应脚本优先匹配；需要确认实际的活动接口路径。临时诊断开启时仍会产生运行记录，取样后应关闭。

本地测试通过不能替代实机查询和领取验收。

## 本地测试

在项目根目录执行：

```powershell
node --test test/*.test.cjs
```

测试使用模拟的 Loon API 和酷狗响应，验证凭证提取、签名、重复领取保护。它不会请求酷狗服务，也不能替代真实设备验收。
